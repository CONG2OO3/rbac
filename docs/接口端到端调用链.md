# RBAC 项目：逐接口前后端调用链

> 基于本仓库当前代码整理。本文的“每个接口”指 **68 个 Controller 映射**，不是把页面地址误当作 API。建议一边开浏览器开发者工具 Network，一边在 IntelliJ IDEA 对照本文设置断点。若代码后来修改，以源码为准。

## 1. 所有接口都会经过的公共链路

```text
页面事件 / onMounted
  → front/src/api/模块函数（少数页面直接调用 request）
  → front/src/api/request.js（Axios，baseURL 默认 /api，附加 Bearer token）
  → 开发环境 Vite /api 代理，或部署后同源 Spring Boot
  → WebMvcConfig 为 @RestController 统一添加 /api 前缀
  → SecurityConfig 的 Sa-Token 拦截器
  → Controller 接收路径、查询、JSON 或 multipart 参数
  → Service 执行业务规则 → Mapper / Redis / 对象存储
  → Result<T> 或二进制响应
  → Axios 响应拦截器解包 data / 抛出业务错误
  → 页面更新表格、弹窗、图表或下载文件
```

关键源码：[request.js](../front/src/api/request.js)、[vite.config.js](../front/vite.config.js)、[WebMvcConfig.java](../backend/src/main/java/com/company/rbac/config/WebMvcConfig.java)、[SecurityConfig.java](../backend/src/main/java/com/company/rbac/config/SecurityConfig.java)、[GlobalExceptionHandler.java](../backend/src/main/java/com/company/rbac/common/exception/GlobalExceptionHandler.java)。

- `/api/auth/login`、`/api/auth/register`、`/api/auth/captcha`、`/api/public/config` 免登录；其他 `/api/**` 先检查 Sa-Token 登录态。`/api/system/**` 和 `/api/business/**` 还会查询用户角色键，要求包含 `admin`。`/api/dashboard/**` 仅要求登录。
- `@OperationLog` 的写接口在 Controller 方法外围经过 `OperationLogAspect`，写入操作日志；未标注的查询接口没有这层操作日志。登录成功或失败的日志由认证代码显式记录，不经过该切面。
- 常规接口返回 `Result<T>`。`request.js` 将 `data` 解包；业务 `code != 200` 转成前端异常，`code == 401` 清除 token 并跳登录。Excel 和文件内容返回二进制，不按普通 JSON 处理。异常通常被 `GlobalExceptionHandler` 转为 `Result.fail(...)`。
- `pageNum`、`pageSize`、`keyword` 常由列表页传入。表格 `records`、`total` 来自 `PageResult`。页面的“重新加载”通常只是再调用同一列表接口。
- 下面表中用 `API 函数 → Controller.方法 → Service/持久层 → 页面效果` 表达链路；表中所有路径均已写出实际的 `/api` 前缀。`{id}`、`{ids}`、`{resource}` 表示动态路径参数。

## 2. 认证与公共配置（5 + 1 个）

源码：[Login.vue](../front/src/views/Login.vue)、[Register.vue](../front/src/views/Register.vue)、[AppLayout.vue](../front/src/layout/AppLayout.vue)、[platformConfig.js](../front/src/api/platformConfig.js)、[AuthController.java](../backend/src/main/java/com/company/rbac/auth/AuthController.java)、[RegistrationService.java](../backend/src/main/java/com/company/rbac/auth/RegistrationService.java)。

| 接口 | 前端入口与 API 函数 | 后端经过什么；返回前端后做什么 |
| --- | --- | --- |
| `GET /api/public/config` | 登录页、注册页、布局、系统配置页 → `loadPublicConfig()` | `SystemConfigController.publicConfig` → `SystemConfigService.publicConfig` 读取 `sys_config` → 返回系统名称、Logo、验证码和注册开关 → 更新响应式 `platformConfig`。公开接口。 |
| `GET /api/auth/captcha` | 登录/注册页在开关开启时刷新验证码 → `getCaptcha()` | `AuthController.captcha` 先读配置开关 → `CaptchaService.create` 生成验证码并把答案存 Redis → 返回验证码 ID 与图片；关闭时返回业务错误。 |
| `POST /api/auth/register` | 注册页提交 → `registerUser(data)` | `AuthController.register` → `RegistrationService.register` 校验注册开关、输入及可能的 Redis 验证码 → BCrypt 加密 → `SystemCrudService.save` 写 `sys_user` 并分配普通用户角色 → 前端成功后跳登录。 |
| `POST /api/auth/login` | 登录页提交 → **直接** `request.post('/auth/login', data)` | `AuthController.login` → 按配置校验 Redis 验证码 → `SysUserMapper` 查 `sys_user`、校验状态及密码，旧明文密码会升级为 BCrypt → 更新登录 IP/时间 → `StpUtil.login` 在 Redis 建立登录态 → `LogService` 写 `sys_login_log` → 返回 token/用户信息，前端保存 token 并跳首页。 |
| `POST /api/auth/logout` | 顶栏退出 → **直接** `request.post('/auth/logout')` | `AuthController.logout` → `StpUtil.logout` 清除当前登录态 → 前端清除本地 token 并跳登录。 |
| `GET /api/auth/info` | 布局初始化 → **直接** `request.get('/auth/info')` | `AuthController.info` → `SysUserMapper` 查当前用户、`SysUserRoleMapper` 查角色键 → 返回用户/角色/权限，布局据此显示用户信息。 |

注意：登录失败时也写 `sys_login_log`。密码错误和验证码错误是不同分支；前端只接收到业务错误信息。`GET /auth/info` 返回的权限数组并不等于已经实现按钮级权限，后端目前主要是登录校验和 `admin` 角色校验。

| --- | --- | --- |

| 接口 | 前端入口与 API 函数 | 后端经过什么；页面效果 |
| --- | --- | --- |
| `POST /api/system/excel/{resource}/export` | 资源页点击导出 → `exportResource(resource)`，`responseType: 'blob'` | `SystemExcelController.export` → `SystemCrudService.all` 查对应表 → 按白名单字段组装数据 → EasyExcel 写 `.xlsx` 响应流 → 浏览器创建下载链接。导出的是该资源全部数据，不是仅当前页。 |

## 6. 文件管理（4 个路由，图片/附件/视频复用）

页面：[FileManagement.vue](../front/src/views/FileManagement.vue)；API：[file.js](../front/src/api/file.js)；后端：[SystemFileController.java](../backend/src/main/java/com/company/rbac/file/controller/SystemFileController.java)、[FileService.java](../backend/src/main/java/com/company/rbac/file/service/FileService.java)。`fileType` 选择 `image`、`attachment`、`video`，是同一套接口，不是三套 Controller。

| 接口 | 前端入口与 API 函数 | 后端经过什么；页面效果 |
| --- | --- | --- |
| `GET /api/system/file/list` | 图片/附件/视频页进入、查询、翻页、切换视图 → `listFiles({fileType,...})` | `SystemFileController.list` → `FileService.list` 查 `sys_file` 元数据，并为文件生成访问 URL → 图片卡片、附件表格或视频列表。 |
| `POST /api/system/file/upload` | 上传框选/拖拽/批量 → 对每个文件调用 `uploadFile(fileType,file)` | `SystemFileController.upload` → `FileService.upload` 校验类型/大小 → `StorageStrategyFactory.current` 选择当前 AliOSS/MinIO/星云图策略上传对象 → 写 `sys_file` → 返回元数据并刷新列表。前端“最多 9 张”是页面层限制，服务端另有类型/大小校验。 |
| `DELETE /api/system/file/{ids}` | 文件删除确认 → `deleteFile(id)` | `SystemFileController.remove` → `FileService.remove` 处理对象存储及 `sys_file` 元数据 → 刷新列表。对象存储策略的远端删除能力可能不同。 |
| `GET /api/system/file/{id}/content?download=false/true` | 附件预览或下载 → `fetchFileContent(id, false/true)` | `SystemFileController.content` → `FileService.get` 查 `sys_file` → `FileService.download` 从所属存储策略读内容 → 设置 `inline`/`attachment` 和文件名，再流式返回 blob → 浏览器预览/下载。图片/视频有时直接使用列表中的访问 URL，不一定调用此接口。 |

## 10. 按一次真实点击完整走读

以“新增部门”为例：

1. 浏览器进入 `/departments`，Vue Router 渲染 `ResourcePage`，`resource='departments'`；`loadRows()` 调 `listResource('departments', ...)`。
2. `system.js` 把 `departments` 映射成 `dept`，Axios 发 `GET /api/system/dept/list?pageNum=1&pageSize=10`。`request.js` 从 `localStorage` 取 token，放进 `Authorization: Bearer ...`。
3. `SecurityConfig` 校验登录，并查 `sys_user_role` 等角色关系，确认 `admin`。`SysDeptController.list` 接参数，`SystemCrudService.depts` 用 Mapper 查 `sys_dept`，`PageResult` 返回 `records/total`。
4. Axios 解包 `Result.data`，`ResourcePage` 用 `records` 渲染表格。用户点击“新增部门”，表单保存时 `submitForm()` 调 `createResource('departments', payload)`。
5. 浏览器发 `POST /api/system/dept`，JSON 在 `@RequestBody SysDept` 中反序列化。再次经过认证/管理员拦截。`@OperationLog` 切面包住 `SysDeptController.add`。
6. `SystemCrudService.save` 插入 `sys_dept`；切面写 `sys_operation_log`。Controller 返回 `Result.success()`；Axios 解包成功后弹窗关闭、`loadRows()` 再发一次 GET，表格显示新部门。
7. 若插入失败，异常经 `GlobalExceptionHandler` 返回失败 `Result`，Axios 抛错，页面显示错误且不关闭弹窗。此时检查 Network 响应、后端日志和数据库表，按顺序定位。

自己练习时按同样的 7 步替换成“分配角色”“上传图片”“新建订单”。这三条链分别覆盖关联表、对象存储和事务，是理解整个项目的核心。

## 11. 建议的断点与核对方法

1. 前端在视图的点击函数、`front/src/api/*.js`、`request.js` 请求/响应拦截器打断点；浏览器 Network 检查 Method、URL、Query、JSON/表单、Authorization、响应体。
2. 后端在 `SecurityConfig`、相应 Controller、Service、Mapper SQL 前后、`GlobalExceptionHandler` 打断点。写接口还可看 `OperationLogAspect`，登录可看 `CaptchaService`、`StpUtil.login`。
3. 对照表数据：系统管理看 `sys_*`，业务看 `biz_*`，访问统计看 `sys_visit_*`；Redis 看验证码/会话键；对象存储看文件内容而 `sys_file` 只看元数据。
4. 对于标注“当前前端无调用”的接口，直接用浏览器 Network 找不到是正常的；可在已登录的 API 调试工具中单独调用，但不要误写成已有页面链路。
5. 本文覆盖 Controller 路由，不覆盖静态页面路径、Vite 热更新、第三方对象存储的外部 HTTP API。文中的相对源码链接可从本 Markdown 文件位置直接打开。

## 12. 请求到达后端后，先经过哪些“关卡”

这里把“路由匹配”“前置拦截”“方法切面”“异常处理”分开，避免把所有机制都叫作拦截器。依据当前仓库，核心源码是 [WebMvcConfig.java](../backend/src/main/java/com/company/rbac/config/WebMvcConfig.java)、[SecurityConfig.java](../backend/src/main/java/com/company/rbac/config/SecurityConfig.java)、[OperationLogAspect.java](../backend/src/main/java/com/company/rbac/log/aspect/OperationLogAspect.java)、[GlobalExceptionHandler.java](../backend/src/main/java/com/company/rbac/common/exception/GlobalExceptionHandler.java)。

```text
HTTP 请求
  → 内嵌 Tomcat / Spring MVC 找到目标路由
    → 如为跨域预检 OPTIONS，由 CORS 配置处理；可能不进入业务方法
  → SaInterceptor.preHandle（仅 /api/**）
    → 非公开接口：StpUtil.checkLogin()，查 Sa-Token 登录态
    → /api/system/** 或 /api/business/**：再查数据库角色键是否含 admin
  → Spring MVC 解析 @PathVariable / @RequestParam / @RequestBody / multipart
  → 若方法有 @OperationLog：进入 AOP around → Controller → Service → Mapper/Redis/存储
    → AOP finally 尝试写操作日志
  → 正常返回 Result<T> / 文件流，或异常交给 GlobalExceptionHandler
```

注意两个严格的先后关系：

1. `WebMvcConfig.configurePathMatch` 在应用启动时把 `@RestController` 路由统一注册为 `/api/...`，**不是每次请求执行一次的拦截器**。例如 `@RequestMapping("/system/dept")` 加 `@PostMapping`，实际路径才是 `/api/system/dept`。
2. `@OperationLog` 仅包住被注解的 Controller 方法。请求如果在 Sa-Token 拦截器阶段被拒绝，Controller 和操作日志 AOP 都不会执行。查询接口通常也没有该 AOP。`GlobalExceptionHandler` 是异常响应兜底，不是允许/拒绝请求的前置关卡。

### 例一：公开的登录请求

`POST /api/auth/login`：请求到达后先匹配 `AuthController.login`。`SaInterceptor` 的第一条规则虽然匹配 `/api/**`，但 `notMatch` 排除了这个路径，因此**不会先要求已有 token**；第二条 `/api/system/**`、`/api/business/**` 也不匹配。Spring 把 JSON 绑定为 `LoginRequest`，然后进入 Controller。Controller 根据配置决定是否调用 `CaptchaService.verify` 校验 Redis 验证码，再查 MySQL 用户、校验密码、调用 `StpUtil.login` 创建 Redis 登录态，并写登录日志。它没有 `@OperationLog`，因此不走操作日志 AOP。若账号密码错误，抛出的 `BusinessException(401, ...)` 最后由 `GlobalExceptionHandler` 转为失败 `Result`；前端 `request.js` 看到业务码 `401` 会清理 token。

### 例二：普通登录用户访问自己的资料

`GET /api/auth/info`：路径不在公开白名单，`SaInterceptor` 的第一条规则执行 `StpUtil.checkLogin()`。Sa-Token 根据请求的 `Authorization: Bearer <token>` 查登录态；没 token、token 过期或 Redis 中找不到会抛 `NotLoginException`，**到此停止，不执行 `AuthController.info`**。如果登录有效，第二条管理员规则不匹配 `/api/auth/info`，因此普通用户也能继续。Controller 根据登录 ID 查 MySQL 的 `sys_user` 和角色表，返回用户资料。没有 `@OperationLog`。

### 例三：普通用户尝试新增部门

`POST /api/system/dept`：第一条规则先检查是否登录；第二条规则因为路径属于 `/api/system/**`，调用 `SysUserRoleMapper.selectRoleKeys(当前登录 ID)` 查询角色键，要求包含 `admin`。如果只有 `user`，抛 `BusinessException(403, "无权访问管理接口")`，**部门 JSON 不会进入 `SysDeptController.add`，数据库不插入，也不会产生这次新增部门的 AOP 操作日志**。前端收到失败 `Result`，由 Axios 拦截器抛出错误，弹窗显示错误。

### 例四：管理员成功新增部门

同一个 `POST /api/system/dept`，如果 token 有效且角色键含 `admin`，前置拦截通过。Spring 将 JSON 绑定为 `SysDept`，调用带 `@OperationLog` 的 `SysDeptController.add`。实际执行顺序是 `OperationLogAspect.around` 开始计时 → `joinPoint.proceed()` → `SystemCrudService.save` → `SysDeptMapper.insert` 写 `sys_dept` → 返回 `Result.success()` → AOP `finally` 写 `sys_operation_log` → 前端刷新 `GET /api/system/dept/list`。如果 Service 抛异常，AOP 仍尝试记一条失败日志，然后异常交给 `GlobalExceptionHandler`；AOP 写日志自身失败会被吞掉，不改变业务结果。

### 例五：管理员读取列表与上传文件的差别

- `GET /api/system/dept/list` 也先走登录校验和 `admin` 角色校验，但 Controller 方法没有 `@OperationLog`，因此**不会因读取列表而写操作日志**。
- `POST /api/system/file/upload` 先经过同样两层检查，再由 Spring 解析 multipart 的 `file` 和 `fileType`，进入 `@OperationLog` AOP，随后调用 `FileService` 与存储策略。AOP 的 `safeArguments` 会排除 `MultipartFile`，不会把文件二进制写到操作日志中。
- `OPTIONS /api/system/file/upload` 若是浏览器跨域预检，Spring MVC 的 CORS 规则负责应答；它不是一次真实上传。当前前端开发代理把浏览器请求转到同源 `/api`，通常不需要浏览器跨域预检。

当前项目没有自定义的 `OncePerRequestFilter` 或完整的 Spring Security 过滤链；依赖里使用的是 `spring-security-crypto` 的密码编码器，不能把它误写为“Spring Security 在前面统一拦截”。如果线上还有 Nginx、宝塔或云防火墙，它们是应用**外部**的关卡，不属于上面这条 Spring Boot 内部链路。
