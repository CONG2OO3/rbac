# RBAC 项目学习与实现教程

> 基于当前仓库源码整理，适合一边打开 IDE 一边跟读。本文件描述的是**现有实现**，不是理想化的功能清单。文末另给出从零正常开发时的顺序、练习和待完善点。阅读时不要把示例数据、页面展示和真实业务接口混为一谈。

如果想按每一个接口从页面点击一路追到数据库、Redis 和对象存储，请接着阅读 [接口端到端调用链](./接口端到端调用链.md)。

## 1. 先用一张图理解项目

```text
浏览器（Vue 3）
  ├─ Vue Router：/login、/users、/business/orders 等页面地址
  ├─ Axios：请求 /api/...，附带 Authorization: Bearer <token>
  └─ localStorage：保存 token、主题颜色、页签等浏览器偏好
          │ HTTP
          ▼
Spring Boot 3（默认 8085）
  ├─ WebMvcConfig：静态页面在 /，REST 接口统一加 /api 前缀
  ├─ SecurityConfig：Sa-Token 登录校验和管理员校验
  ├─ Controller：接收参数，返回 Result<T> / 文件流
  ├─ Service：业务规则、事务、调用 Mapper 或存储策略
  ├─ Mapper：MyBatis-Plus / 手写 SQL
  └─ AOP：记录部分写操作的操作日志
          ├─ MySQL：用户、角色、菜单、订单、文件元数据、日志、访问统计
          ├─ Redis：Sa-Token 登录态、验证码
          └─ OSS / MinIO / 星云图：文件内容
```

一个很重要的概念：`/users` 是**前端页面路由**，`/api/system/user/list` 是**后端数据接口**。访问页面时，Spring Boot 返回 `index.html`；页面里的 JavaScript 再请求接口。不要把两类 URL 混淆。

## 3. 启动配置与数据库

### 3.1 环境配置

- `backend/src/main/resources/application.yml`：通用端口、上传大小、MyBatis-Plus、Sa-Token。默认端口为 `8085`，默认激活 `prod`。
- `application-test.yml`：本地测试连接参数，`spring.sql.init.mode=always`，会执行资源目录里的 `schema.sql` 和 `data.sql`。
- `application-prod.yml`：生产连接参数，`spring.sql.init.mode=never`，**不会自动建表**。真实凭据应通过环境变量或受保护的外部配置传入，不应依赖配置文件里的默认密码。
- `front/vite.config.js`：开发服务器端口 `5173`，将 `/api` 代理到本地后端 `8085`。
- `front/src/api/request.js`：Axios 默认 `baseURL='/api'`，因此模块 API 文件里只写 `/auth/login` 一类相对路径。

第一次学习建议用独立的本地测试库和 Redis，不要直接在现有生产库上练习增删改。已运行中的数据库不要盲目重复执行增量 SQL；先比对表结构及执行历史。

### 3.2 表如何分组

| 领域 | 表 | 作用 |
| --- | --- | --- |
| 用户与权限 | `sys_user`、`sys_role`、`sys_menu`、`sys_dept`、`sys_post` | 主数据 |
| 多对多关系 | `sys_user_role`、`sys_role_menu` | 用户关联角色、角色关联菜单 |
| 动态配置 | `sys_config` | `system.*`、`login.*`、`register.*`、`storage.*` 键值 |
| 日志 | `sys_login_log`、`sys_operation_log` | 登录结果、带注解接口的操作记录 |
| 文件 | `sys_file` | 文件名、类型、对象 key、所用存储类型；**不是文件本体** |
| 访问统计 | `sys_visit_daily`、`sys_visit_visitor` | 每日 PV/UV 与访客去重 |
| 业务 | `biz_product`、`biz_order`、`biz_order_item` | 产品、订单主表、订单行 |

完整建表参考 `backend/src/main/resources/schema.sql`。`db/` 中的文件是按功能追加的脚本：`system_config.sql`、`log_module.sql`、`file_module.sql`、`visit_module.sql`、`business_module.sql`。生产环境不会自动执行它们。

`BaseEntity` 包含创建/更新时间和 `deleted`；`AuditMetaObjectHandler` 尝试自动填时间与删除标记；`@TableLogic` 让常规 MyBatis-Plus 删除成为逻辑删除。但少数场景（例如用户重建同名账号、删除产品）调用了自定义**物理删除** SQL，读代码时务必区分。

## 4. 一次请求到底经过哪里

以“用户管理列表”为例：

1. 访问 `/users`，Vue Router 渲染 `ResourcePage.vue`，并把 `resource='users'` 传给它。
2. 页面 `loadRows()` 调用 `front/src/api/system.js` 的 `listResource('users', params)`。
3. `request.js` 发出 `GET /api/system/user/list?pageNum=1&pageSize=10`，若浏览器有 token，会加 `Authorization: Bearer ...`。
4. 开发模式由 Vite 代理到 `8085`；同包部署时由同一个 Spring Boot 接收。
5. `SecurityConfig` 对 `/api/**` 检查登录，对 `/api/system/**` 额外检查管理员角色。
6. `SysUserController.list()` 调 `SystemCrudService.users()`；通用 `page()` 使用 `QueryWrapper` 拼关键字查询，再由 `SysUserMapper` / MyBatis-Plus 查询 MySQL。
7. `PageResult.of()` 把 MyBatis-Plus 分页对象变成 `records`、`total`、`pageNum`、`pageSize`；`Result.success()` 再加 `code=200`。
8. Axios 响应拦截器拆出 `data`；Vue 用响应式 `records` 更新表格。

正常成功响应形状如下：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [],
    "total": 0,
    "pageNum": 1,
    "pageSize": 10
  }
}
```

`GlobalExceptionHandler` 把多数异常变成 `Result.fail(...)`。因此学习调试时**不能只看 HTTP 状态码**：本项目不少业务错误仍以 HTTP 200 返回，真正结果在 JSON 的 `code` 中。前端 `request.js` 正是按 `body.code` 判断成功或失败。

## 5. 接口总览：地址、代码和业务动作

下表的路径都是**实际完整路径**。`WebMvcConfig` 会给每个 `@RestController` 的映射统一加 `/api`；Controller 文件里通常只写 `/auth`、`/system/user` 等。

### 5.1 认证与公开配置

主要看 `AuthController`、`CaptchaService`、`RegistrationService`、`SystemConfigService`，前端看 `Login.vue`、`Register.vue`、`platformConfig.js`。

| 方法与接口 | 实现动作 |
| --- | --- |
| `GET /api/public/config` | 读 `sys_config`，返回系统名称、描述、Logo 地址、验证码/注册开关；无需登录。 |
| `GET /api/auth/captcha` | 开启验证码时随机生成四位字符，Redis 保存 `captcha:<id>`，有效期 5 分钟，返回 Base64 PNG 和 id。 |
| `POST /api/auth/register` | 检查注册开关、输入格式和可选验证码；BCrypt 加密密码；新增用户并关联 `user` 普通角色。 |
| `POST /api/auth/login` | 查询用户、验证状态和密码；可选验证码；写登录 IP/时间；Sa-Token 创建登录态；写登录日志；返回 token。 |
| `GET /api/auth/info` | 根据当前 token 的用户 id 查询用户和角色，供前端决定显示哪组导航。 |
| `POST /api/auth/logout` | 调 `StpUtil.logout()`，让当前登录态失效。 |

登录链路可按这个顺序单步调试：`Login.vue submit()` → `request.post('/auth/login')` → `SecurityConfig` 放行登录端点 → `AuthController.login()` → `SysUserMapper` → `StpUtil.login()` → Redis → `LogService.recordLogin()` → 返回 token → 浏览器 `localStorage`。之后的请求由 Axios 自动带 Bearer token。

验证码验证使用 Redis 的 `getAndDelete`，所以**同一验证码只能使用一次**。注册开关由后端再次判断，绝不只靠隐藏前端“注册”入口。登录代码仍兼容旧明文密码，成功登录时才升级为 BCrypt；这是迁移兼容逻辑，不是新系统应采用的常规做法。

### 5.2 系统管理五类主数据

五个 Controller 都调用 `SystemCrudService`，对应 MyBatis-Plus Mapper 和同名 `sys_*` 表；前端统一由 `ResourcePage.vue` + `front/src/api/system.js` 复用表格与表单。

| 资源 | 列表 | 新增 | 修改 | 删除 | 额外接口 |
| --- | --- | --- | --- | --- | --- |
| 用户 `user` | `GET /api/system/user/list` | `POST /api/system/user` | `PUT /api/system/user` | `DELETE /api/system/user/{ids}` | `GET /{id}`、`GET /{id}/roles`、`PUT /{id}/roles`，前缀同左 |
| 角色 `role` | `GET /api/system/role/list` | `POST /api/system/role` | `PUT /api/system/role` | `DELETE /api/system/role/{ids}` | `GET /{id}/menus`、`PUT /{id}/menus`，前缀同左 |
| 菜单 `menu` | `GET /api/system/menu/list` | `POST /api/system/menu` | `PUT /api/system/menu` | `DELETE /api/system/menu/{ids}` | `GET /api/system/menu/tree` |
| 部门 `dept` | `GET /api/system/dept/list` | `POST /api/system/dept` | `PUT /api/system/dept` | `DELETE /api/system/dept/{ids}` | 无 |
| 岗位 `post` | `GET /api/system/post/list` | `POST /api/system/post` | `PUT /api/system/post` | `DELETE /api/system/post/{ids}` | 无 |

`{ids}` 可以是一个 id，也可以是逗号分隔的多个 id；Controller 拆分后交给 Service。五种列表使用 `pageNum`、`pageSize`、`keyword`。用户列表搜索账号、昵称、手机号；部门搜索名称、负责人、电话等，具体字段见 `SystemCrudService.page()` 的调用。

授权是多对多关系：`PUT /api/system/user/{id}/roles` 先删 `sys_user_role` 原关系再插入新角色；`PUT /api/system/role/{id}/menus` 同理更新 `sys_role_menu`。`GET` 接口则返回已关联的 id 数组。当前侧栏菜单写在 `AppLayout.vue` 的 `allGroups` 中，**不是**从 `sys_menu` 动态生成；角色菜单关联目前也未落实为每个接口的细粒度权限校验。当前后端的主要权限边界是“已登录”和“有 `admin` 角色”。

用户删除与重新创建同名用户：`SysUserMapper` 提供查询已删除账号及物理删除方法，`SystemCrudService.save(SysUser)` 在插入前处理旧记录，避免唯一索引 `user_name` 冲突。对比 `BaseEntity` 的一般逻辑删除，这是一处值得研究的特例。

### 5.3 Excel 导入导出

主要看 `SystemExcelController` → `SystemCrudService.all()` / `importRows()` → EasyExcel；前端看 `system.js` 的 `exportResource()`、`importResource()`。

| 方法与接口 | 实现动作 |
| --- | --- |
| `POST /api/system/excel/{resource}/export` | 只支持 `users`、`roles`、`menus`、`departments`、`positions`；读取全部记录，按白名单字段写 `.xlsx` 响应流。 |
| `POST /api/system/excel/{resource}/import` | 接收 `multipart/form-data` 的 `file`，按首行表头之后的数据读取，映射成字段值，再逐行调用 CRUD 保存。 |

这里最值得学的是**字段白名单**：不能让客户端任意指定数据库列。但现有导入是逐行处理，未用一个覆盖全部行的事务；用户导入字段中也没有密码列，而数据库的用户密码不能为空，因此不能把此实现视作成熟的数据迁移方案。

### 5.4 系统配置与存储配置

系统配置都由 `SystemConfigController` 暴露，真正读写在 `SystemConfigService`、`StorageSettingsService`，保存到 `sys_config`。

| 方法与接口 | 实现动作 |
| --- | --- |
| `GET /api/system/config` | 管理员读取系统名称、描述、Logo 和两个开关。 |
| `PUT /api/system/config/system` | 修改系统名称和描述。 |
| `PUT /api/system/config/login` | 修改是否启用验证码，JSON 形如 `{"enabled":true}`。 |
| `PUT /api/system/config/register` | 修改是否允许自主注册，JSON 形如 `{"enabled":true}`。 |
| `POST /api/system/config/logo` | 上传不超过 2 MB 的图片，复用文件服务，并把文件 id 写入配置。 |
| `DELETE /api/system/config/logo` | 清除 Logo 配置引用。 |
| `GET /api/system/config/storage` | 返回当前策略和三种存储的非密钥配置；仅返回“是否已设置密钥”，不回显密钥。 |
| `PUT /api/system/config/storage` | 校验并保存阿里 OSS、MinIO 或星云图配置，设置 `storage.active_type`。 |

前端 `SystemSettings.vue` 用 tab 切换各配置；`platformConfig.js` 用响应式对象把系统名称、Logo、登录开关同步到登录页和导航栏。存储配置保存后，下一次上传调用 `StorageStrategyFactory.current()`，因此**不需要专门增加新的上传接口**。历史文件仍按数据库记录的 `storage_type` 找原策略下载；切换策略后不能随意删除旧服务配置。

### 5.5 文件管理

`SystemFileController` 统一处理图片、附件、视频三种 `fileType`；`FileService` 管元数据及校验，`StorageStrategyFactory` 选择实现，`StorageStrategy` 定义 `upload/download/delete/temporaryUrl` 四个动作。

| 方法与接口 | 实现动作 |
| --- | --- |
| `GET /api/system/file/list?fileType=image` | 按图片/附件/视频分页读 `sys_file`，并尝试为每条记录生成临时访问 URL。 |
| `POST /api/system/file/upload?fileType=image` | 接收单个 `file`，校验类型/大小；上传对象存储；再写 `sys_file`；返回元数据和 URL。 |
| `DELETE /api/system/file/{ids}` | 找每条记录使用的存储策略，删除对象及元数据。 |
| `GET /api/system/file/{id}/content?download=false` | 从对象存储取文件流；`download=false` 为 inline 预览，`true` 为附件下载。 |

上传的典型顺序是：浏览器文件 → `FileManagement.vue` 创建 `FormData` → `uploadFile()` → Controller → `FileService.upload()` → 工厂选择当前策略 → 上传对象 → 插入 `sys_file`。若数据库插入失败，Service 尝试删除刚上传的对象作为补偿。图片/附件限制 50 MB，视频限制 500 MB；图片页面一次最多选 9 张，但前端是**逐张请求**，不是后端单请求接收 9 张。

三种策略：`AliyunOssStorageStrategy` 使用 OSS SDK；`MinioStorageStrategy` 使用 MinIO SDK，上传前确认 bucket；`StarimgStorageStrategy` 使用 HTTP multipart 和 `X-API-Key`，仅能上传图片。星云图删除只删除本系统记录，图床内容未必删除。文件预览由前端根据扩展名选择：PDF、DOCX、Excel、文本以及视频；旧 `.doc` 当前不支持浏览器直接预览。

### 5.6 日志

| 方法与接口 | 实现动作 |
| --- | --- |
| `GET /api/system/log/login/list` | 分页查询 `sys_login_log`，支持关键字和状态。 |
| `GET /api/system/log/operation/list` | 分页查询 `sys_operation_log`。 |
| `DELETE /api/system/log/login/{ids}` | 删除指定登录日志。 |
| `DELETE /api/system/log/operation/{ids}` | 删除指定操作日志。 |
| `DELETE /api/system/log/login/clear` | 清空登录日志。 |
| `DELETE /api/system/log/operation/clear` | 清空操作日志。 |

登录日志由 `AuthController.login()` 显式调用 `LogService.recordLogin()`，记录成功、密码错误或验证码错误。操作日志则是 `@OperationLog` + `OperationLogAspect`：切面包住 Controller 方法，记录模块、操作名、URL、请求方法、操作者、耗时、成功/失败，写入 `sys_operation_log`。切面会排除上传文件和存储密钥输入，且尝试遮蔽 JSON 中的 `password`；日志保存失败不会中断原业务请求。

### 5.7 系统监控与访问趋势

| 方法与接口 | 实现动作 |
| --- | --- |
| `GET /api/system/monitor/server` | JVM/操作系统指标、磁盘容量、线程、运行时间，并分别检测 MySQL `SELECT 1` 和 Redis `PING`。 |
| `GET /api/system/monitor/online` | 扫描 Redis 中的 Sa-Token token 键，汇总在线用户并在内存中筛选/分页。 |
| `DELETE /api/system/monitor/online/{sessionId}` | 找到对应 token，禁止踢出自己，再调用 Sa-Token 强制下线。 |
| `POST /api/dashboard/visit` | 记录一次访问：每日 `pv + 1`，用户当天首次出现才 `uv + 1`。 |
| `GET /api/dashboard/traffic?range=7d` | 查询近 7 天、30 天或 1 年趋势；补零并返回今日与区间 PV/UV。 |

`ServerMonitor.vue` 使用 ECharts 绘制服务数据；`OnlineUsers.vue` 是表格。注意“在线用户”按 Redis token 扫描，数据量大时仍需重新设计分页策略。这里的 UV 定义是**去重登录用户**，不是按 Cookie、设备或真实自然人去重。首页 `Dashboard.vue` 的访问趋势是真接口；但首页四张统计卡片、公告、最近操作和多数状态文字仍是固定演示值。

### 5.8 业务管理：产品和订单

主要看 `BusinessController` → `BusinessService` → `BizProductMapper`、`BizOrderMapper`、`BizOrderItemMapper`，前端是 `ProductManagement.vue`、`OrderManagement.vue`。

| 方法与接口 | 实现动作 |
| --- | --- |
| `GET /api/business/products` | 按关键字、状态分页查询产品。 |
| `GET /api/business/products/options` | 查询状态正常的产品，供订单下拉框选择。 |
| `POST /api/business/products` | 验证编码、名称、价格、库存；检查编码重复；新增产品。 |
| `PUT /api/business/products/{id}` | 锁定产品后修改；返回产品 id。 |
| `DELETE /api/business/products/{id}` | 若已被订单行引用，则拒绝删除，建议停用。 |
| `GET /api/business/orders` | 按单号/客户、状态分页查询订单。 |
| `GET /api/business/orders/{id}` | 返回订单主表和订单行列表。 |
| `POST /api/business/orders` | 校验客户与订单行、生成单号、计算快照金额、预占库存、写主表和明细。 |
| `PUT /api/business/orders/{id}` | 只允许修改 `NEW` 订单；先恢复旧明细库存，再按新明细预占，重写订单行。 |
| `PUT /api/business/orders/{id}/status` | 按状态机变更；取消订单时恢复库存。 |
| `DELETE /api/business/orders/{id}` | 只允许删除 `NEW` / `CANCELLED`；删除 `NEW` 时恢复库存。 |

订单状态流转是 `NEW → CONFIRMED → SHIPPED → COMPLETED`，同时 `NEW` 或 `CONFIRMED` 可以转 `CANCELLED`。`BusinessService` 使用 `@Transactional` 保证订单主表、订单行和库存一起提交/回滚；`BizProductMapper.selectForUpdate()` 加行锁，`reserveStock()` 的 SQL 还要求 `stock >= quantity`，防止并发超卖。订单行保存产品编码、名称、单价快照，所以后续改产品价格不会篡改旧订单金额。读完 CRUD 后再研究这个模块，是理解事务和并发的最好练习。

## 6. 前端页面与真实数据的边界

| 页面或功能 | 当前数据来源 | 阅读提示 |
| --- | --- | --- |
| 登录、注册、验证码 | 后端接口 | `Login.vue` / `Register.vue` 调 `platformConfig.js` 和 `request.js`。 |
| 用户、角色、菜单、部门、岗位 | 后端接口 | 共用 `ResourcePage.vue`，不是五份完全独立页面。 |

| 首页统计卡片、公告、最近操作、部分状态 | 组件中的静态数组 | 看起来像实时数据，但目前不是。 |
| 个人中心资料、修改密码、页面内登录日志 | 静态示例 | `Profile.vue` 的“保存密码”仅切换成功提示，**没有改密码接口调用**。 |

## 7. 如果从零正常实现，推荐什么顺序

不要先做完整 UI 再一次性补后台，也不要把全部 Controller 写完才联调。更容易掌握的方法是**先搭基础，再按一个个纵向功能切片完成“表 → 后端 → 前端 → 测试”**。

| 阶段 | 先做什么 | 完成标准 |
| --- | --- | --- |
| 0. 需求和契约 | 列页面、字段、角色、操作；区分真实数据与演示数据；画 ER 图和接口清单 | 能回答“数据存哪里、谁能操作、失败时怎样返回”。 |
| 1. 基础工程 | 初始化 Spring Boot / Vue、MySQL / Redis 配置、`Result`、异常处理、Axios 封装、路由 | 一个公开接口可从浏览器走通到后端。 |
| 2. 表结构 | 先建用户/角色/关联表，创建可重复的迁移脚本和最小种子数据 | 空库能可靠初始化；不依赖手工在 Navicat 改表。 |
| 3. 认证 | 用户查询、BCrypt、登录/退出、Sa-Token、Redis、前端守卫 | 无 token 不能访问受保护接口；登录后可刷新页面。 |
| 4. 最小 RBAC | 用户 CRUD、角色 CRUD、用户-角色关系；再菜单及角色-菜单关系 | 至少能新增用户、赋角色、按权限访问接口。 |
| 5. 组织与系统配置 | 部门、岗位、配置键值、验证码、注册开关 | 变更配置后，不修改代码就能在登录/注册流程生效。 |
| 6. 业务切片 | 先产品，再订单列表/详情，再下单、库存、状态流转 | 并发下不会卖出负库存；失败可回滚。 |
| 7. 文件切片 | 先文件元数据与一种存储，再抽象 `StorageStrategy`，最后加其他提供商与预览 | 切换存储后，新旧文件都可访问。 |
| 8. 横切能力 | AOP 操作日志、登录日志、Excel、监控、PV/UV | 失败操作能定位；导入导出有边界与错误报告。 |
| 9. 完善前端 | 删演示数据、完成个人中心、通知、真实首页统计；统一加载/空态/错误态 | 每个可点击入口有真实行为或明确禁用。 |
| 10. 测试与部署 | 单元/集成测试、环境变量、构建 Vue、复制 `dist`、打 JAR、上线 | 生产环境重启和页面刷新均正常，凭据不进入仓库。 |

每一阶段建议只选择**一个端到端场景**作为验收，而不是以“代码文件都创建了”为完成标准。例如第 4 阶段先实现“新增用户 → 列表能看到 → 分配角色 → 重新登录验证权限”，再扩展其他实体。

### 7.1 建议亲手重写的三个练习

1. **用户列表与新增**：自己写一遍 `sys_user` 表、Entity、Mapper、Service、Controller、Axios、Vue 表单。练习分页、关键词、字段校验和唯一约束。
2. **登录与鉴权**：从空白项目实现 BCrypt 登录、Sa-Token、Redis、Axios token 注入、401 处理。故意断开 Redis，观察异常从哪一层出现。
3. **订单下单**：不看现有代码先设计库存预占和事务，再对照 `BusinessService.saveOrder()`；写两个并发请求争抢最后一件库存的测试。

## 9. 调试方法与具体示例

### 9.1 本地联调检查顺序

1. 确认 MySQL、Redis 本身可连，且**运行后端的机器**能连，不要只以 Navicat 能连为依据。
2. 看 IDEA 启动日志，确认激活的 profile、端口和数据库连接；不要在截图或文档中暴露密码。
3. 浏览器打开 `/api/public/config`，检查 JSON；再打开 `/login`，检查 Vue 是否加载。
4. 登录失败时查看浏览器 Network 中 `/api/auth/login` 的响应 `code`，再看后端异常根因和 Redis 连接。
5. 登录成功后检查 `localStorage.access_token`，再看列表请求是否有 `Authorization: Bearer ...`。
6. 列表为空时，先查数据库表，再查接口响应；不要先怀疑 Vue 表格。

例如用户列表可用浏览器 Network 对照 `GET /api/system/user/list?pageNum=1&pageSize=10`，前端看 `ResourcePage.loadRows()`，后端在 `SysUserController.list()` 和 `SystemCrudService.page()` 下断点。密码、token 和对象存储密钥不要写入文档或提交代码。

### 9.2 前后端同包部署为什么可行

`front/dist` 的**内容**复制到 `backend/src/main/resources/static/`，Maven 会把它们打入 JAR。`WebMvcConfig` 让 REST Controller 统一位于 `/api`，并让 `/login`、`/users` 等 Vue 页面地址刷新时转发到 `index.html`。所以一个 Spring Boot 进程既能返回前端静态资源，又能处理数据接口。新增 Vue Router 页面时，记得同步增加后端 SPA 回退路径。

已有 `dist` 时可以运行 `backend/deploy-frontend.ps1` 只复制；前端源码变更后才运行 `backend/deploy-frontend.ps1 -Build`，再执行 Maven 打包。`npm run build` 不是日常每改一行都要运行的步骤。

## 10. 现有实现的边界与改进优先级

这些不是让你现在直接改生产系统，而是阅读代码时应能识别的工程问题：

1. **密码安全优先**：`AuthController` 为兼容旧数据仍接受明文密码；管理端 `SystemCrudService.save(SysUser)` 直接插入传入的密码，未像自主注册那样统一 BCrypt。应在服务层统一加密和校验，逐步迁移旧账号，移除明文兜底。生产配置中的密码默认值也应移出仓库并轮换。
2. **权限尚未闭环**：`sys_role_menu` 可以保存授权，但页面菜单来自前端硬编码，接口只做管理员粗粒度检查；“分配菜单”不等于真正按菜单权限控制接口。应设计权限标识到接口和前端导航的完整映射。
3. **前端演示内容尚在**：个人中心修改密码、通知、数据管理、首页部分卡片还不是实时功能，不能作为已交付的真实业务来依赖。
4. **批量操作的原子性**：导入逐行写入、用户/角色菜单关系先删后插等路径缺少完整事务或详细失败报告；异常时可能留下部分结果。
5. **跨系统删除的一致性**：文件删除先操作对象存储再删除数据库；数据库失败时无法靠 MySQL 事务自动恢复对象。成熟实现可考虑异步任务、软删除和重试补偿。
6. **错误与日志脱敏**：全局异常处理可能把内部异常消息直接返给客户端；AOP 当前主要按字段名遮蔽 `password`，仍应进一步审计手机号、密钥、token 等敏感信息。
7. **测试覆盖不足**：当前自动化测试主要集中在存储策略。登录、权限、CRUD、库存并发、Excel、SPA 路由都值得补单元/集成测试。

学习的目标不是一口气把以上问题全部修完，而是先能准确解释现有行为，再为每项改动写出“预期、测试、回滚”三件事。
