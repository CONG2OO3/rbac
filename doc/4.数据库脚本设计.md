## 设计原则

1. **统一字符集**：所有表使用 `utf8mb4`，排序规则 `utf8mb4_unicode_ci`
2. **存储引擎**：统一使用 `InnoDB`
3. **主键策略**：使用 `BIGINT` 自增或雪花算法 ID
4. **软删除**：业务表统一使用 `deleted` 字段，禁止物理删除
5. **审计字段**：每张表必须包含创建/更新时间和操作人
6. **表前缀**：系统表 `sys_`，业务表 `biz_`，日志表 `log_`

## 命名规范

### 表名

```
{前缀}_{业务模块}_{实体名}

示例：
sys_user          系统用户表
sys_role          系统角色表
sys_menu          系统菜单表
sys_dept          系统部门表
biz_order         业务订单表
log_oper          操作日志表
```

### 字段名

```
小写字母 + 下划线，见名知意

✅ user_name, create_time, order_status
❌ userName, CreateTime, status1
```

### 索引名

```
idx_{表名}_{字段名}        普通索引
uk_{表名}_{字段名}         唯一索引
pk_{表名}                  主键（默认）
```

## 标准字段

每张业务表必须包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增或雪花 ID |
| `create_time` | DATETIME | 创建时间，默认 CURRENT_TIMESTAMP |
| `update_time` | DATETIME | 更新时间，ON UPDATE CURRENT_TIMESTAMP |
| `create_by` | VARCHAR(64) | 创建人 |
| `update_by` | VARCHAR(64) | 更新人 |
| `deleted` | TINYINT(1) | 软删除：0-未删除，1-已删除 |

### 标准字段 DDL 片段

```sql
`id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
`create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
`create_by`   VARCHAR(64)  DEFAULT '' COMMENT '创建人',
`update_by`   VARCHAR(64)  DEFAULT '' COMMENT '更新人',
`deleted`     TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '删除标志（0-未删除 1-已删除）',
PRIMARY KEY (`id`)
```

## 系统表结构

### sys_user — 用户表

```sql
CREATE TABLE `sys_user` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `user_name`   VARCHAR(30)  NOT NULL COMMENT '用户账号',
  `nick_name`   VARCHAR(30)  NOT NULL COMMENT '用户昵称',
  `email`       VARCHAR(50)  DEFAULT '' COMMENT '邮箱',
  `phone`       VARCHAR(11)  DEFAULT '' COMMENT '手机号码',
  `sex`         CHAR(1)      DEFAULT '0' COMMENT '性别（0-男 1-女 2-未知）',
  `avatar`      VARCHAR(255) DEFAULT '' COMMENT '头像地址',
  `password`    VARCHAR(100) DEFAULT '' COMMENT '密码（BCrypt 加密）',
  `status`      CHAR(1)      DEFAULT '0' COMMENT '状态（0-正常 1-停用）',
  `dept_id`     BIGINT       DEFAULT NULL COMMENT '部门ID',
  `login_ip`    VARCHAR(128) DEFAULT '' COMMENT '最后登录IP',
  `login_time`  DATETIME     DEFAULT NULL COMMENT '最后登录时间',
  `remark`      VARCHAR(500) DEFAULT NULL COMMENT '备注',
  `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `create_by`   VARCHAR(64)  DEFAULT '' COMMENT '创建人',
  `update_by`   VARCHAR(64)  DEFAULT '' COMMENT '更新人',
  `deleted`     TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '删除标志',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_sys_user_user_name` (`user_name`),
  KEY `idx_sys_user_dept_id` (`dept_id`),
  KEY `idx_sys_user_phone` (`phone`)
```

```sql
  KEY `idx_biz_{module}_status` (`status`)
```

## 索引设计

### 索引原则

1. 主键自动创建聚簇索引
2. 频繁作为 WHERE 条件的字段建索引
3. 唯一业务字段建唯一索引
4. 联合索引遵循最左前缀原则
5. 单表索引数量建议不超过 5 个

### 常见索引场景

| 场景 | 索引类型 | 示例 |
|------|----------|------|
| 唯一业务键 | UNIQUE | `uk_sys_user_user_name` |
| 外键关联 | INDEX | `idx_sys_user_dept_id` |
| 状态筛选 | INDEX | `idx_biz_order_status` |
| 时间范围查询 | INDEX | `idx_biz_order_order_time` |
| 组合查询 | 联合 INDEX | `idx_biz_order_status_time (status, order_time)` |

## 脚本管理

### 目录结构

```
backend/src/main/resources/db/
├── schema.sql              # 全量建表脚本（新环境初始化）
├── data.sql                # 初始数据（管理员、菜单、角色等）
├── migration/              # 增量变更脚本
│   ├── V1.0.0__init.sql
│   ├── V1.1.0__add_order_table.sql
│   └── V1.1.1__add_order_index.sql
└── rollback/               # 回滚脚本
    ├── V1.1.0__rollback_order_table.sql
    └── V1.1.1__rollback_order_index.sql
```

### 脚本命名规范

```
V{版本号}__{描述}.sql

示例：
V1.0.0__init.sql                    初始化
V1.1.0__add_biz_order_table.sql     新增订单表
V1.1.1__add_biz_order_index.sql     新增索引
V1.2.0__alter_sys_user_add_field.sql 修改用户表
```

### 执行方式

```bash
# 新环境：全量初始化
mysql -u rbac -p rbac < backend/src/main/resources/db/schema.sql
mysql -u rbac -p rbac < backend/src/main/resources/db/data.sql

# 增量升级：按版本顺序执行
mysql -u rbac -p rbac < backend/src/main/resources/db/migration/V1.1.0__add_biz_order_table.sql
```

## 变更管理

### 变更流程

```
1. 编写 migration SQL → 2. 本地验证 → 3. 提交 PR Review → 4. 测试环境执行 → 5. 生产环境执行
```

### ALTER 表示例

```sql
-- V1.2.0__alter_sys_user_add_field.sql
```
