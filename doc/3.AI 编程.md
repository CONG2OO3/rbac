## AI 编程概述

AI 编程助手可以显著加速脚手架项目的开发，尤其在以下环节：

| 环节 | AI 能做什么 | 人工需确认 |
|------|-------------|-----------|
| 数据库设计 | 生成 DDL、索引建议 | 业务字段、性能评估 |
| 后端 CRUD | 生成 Entity/Mapper/Service/Controller | 业务逻辑、权限注解 |
| 前端页面 | 生成列表/表单/对话框组件 | UI 交互、权限按钮 |
| 接口文档 | 生成 Swagger 注解 | 接口契约一致性 |
| 单元测试 | 生成测试用例骨架 | 边界条件、Mock 策略 |
| Bug 修复 | 分析堆栈、建议修复 | 根因验证、回归测试 |

## 项目上下文配置

让 AI 准确理解项目，需要配置 Rules 和上下文文件。

### 创建 Cursor Rules

在项目根目录创建 `.cursor/rules/project.mdc`：

```markdown
# 企业开发脚手架项目规范

## 技术栈
- 后端：Java 17 + Spring Boot 3 + MyBatis-Plus + Spring Security + JWT
- 前端：Vue 3 + TypeScript + Element Plus + Pinia + Vite
- 数据库：MySQL 8.0，表前缀 sys_（系统表）、biz_（业务表）
- 缓存：Redis 7.x

## 代码规范
- 后端统一返回 Result<T> 包装
- 前端 API 请求使用 @/utils/request 封装
- 权限注解：@PreAuthorize("@ss.hasPermi('system:user:list')")
- 分页参数：pageNum, pageSize，返回 PageResult<T>

## 目录约定
- 后端包路径：com.company.rbac
- 前端页面：src/views/{module}/{page}/index.vue
- SQL 脚本：backend/src/main/resources/db/

## 禁止事项
- 不要硬编码密码、密钥
- 不要跳过权限校验
- 不要使用 System.out.println，使用 Slf4j 日志
```

## 典型使用场景

### 场景 1：新增业务模块（数据库 → 后端 → 前端）

**Step 1：设计数据库**

```
Prompt：
根据以下业务需求，设计 MySQL 表结构，遵循项目规范（见 @doc/4.数据库脚本设计.md）：

业务：订单管理
字段：订单号、客户名称、金额、状态（待支付/已支付/已取消）、下单时间

要求：
1. 表名 biz_order
2. 包含标准字段 id, create_time, update_time, deleted, create_by, update_by
3. 输出 DDL 和初始索引
```

**Step 2：生成后端代码**

```
Prompt：
基于 @backend/src/main/java/.../entity/SysUser.java 的风格，
为 biz_order 表生成完整后端代码：

1. Entity: BizOrder
2. Mapper: BizOrderMapper + XML
3. Service: IBizOrderService + BizOrderServiceImpl
4. Controller: BizOrderController
5. DTO: BizOrderQueryDTO, BizOrderVO

接口：
- GET  /business/order/list     分页列表
- GET  /business/order/{id}     详情
- POST /business/order          新增
- PUT  /business/order          修改
- DELETE /business/order/{ids}  批量删除

权限前缀：business:order
遵循 @doc/5.API 接口设计.md 规范
```

**Step 3：生成前端页面**

```
Prompt：
参考 @frontend/src/views/system/user/index.vue 和 @原型图.jpg 的 UI 风格，
生成订单管理页面 src/views/business/order/index.vue：

功能：
- 搜索：订单号、客户名称、状态、下单时间范围
- 表格：订单号、客户名称、金额、状态（Tag 展示）、下单时间、操作
- 新增/编辑对话框
- 批量删除
- 权限按钮：business:order:add/edit/remove

使用 Element Plus，API 调用放在 @/api/business/order.ts
```

## AI 辅助开发流程

### 推荐工作流

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  需求描述    │ →  │  AI 生成     │ →  │  人工 Review │
│  + 上下文    │    │  初版代码    │    │  + 调整     │
└─────────────┘    └─────────────┘    └──────┬──────┘
                                              │
┌─────────────┐    ┌─────────────┐    ┌──────▼──────┐
│  合并发布    │ ←  │  测试通过    │ ←  │  联调测试    │
└─────────────┘    └─────────────┘    └─────────────┘
```

### 分步迭代策略

1. **先骨架后细节**：先生成整体结构，再逐方法完善
2. **小步提交**：每个 AI 生成的模块独立提交，便于回滚
3. **测试驱动**：生成代码后立即让 AI 生成对应测试
4. **对照原型**：前端生成后对照 `原型图.jpg` 检查 UI 一致性

### Agent 模式使用建议

Cursor Agent 模式适合：

- 跨多文件的功能开发（如完整 CRUD 模块）
- 重构（如统一异常处理）
- 文档批量生成

不适合：

- 涉及生产密钥、密码的配置
- 未经验证的数据库结构变更
- 直接合并未经 Review 的代码

## 质量保障

### AI 输出必检清单

**后端代码**
- [ ] 权限注解 `@PreAuthorize` 是否添加
- [ ] 参数校验 `@Valid` / `@NotBlank` 是否完整
- [ ] 事务注解 `@Transactional` 是否正确
- [ ] SQL 是否使用参数化查询（MyBatis `#{}`）
- [ ] 日志是否使用 Slf4j，无敏感信息
- [ ] 返回类型是否为 `Result<T>`

**前端代码**
- [ ] API 是否使用 `@/utils/request` 封装
- [ ] 权限按钮是否使用 `v-hasPermi` 指令
- [ ] 表单是否有校验规则
- [ ] 是否正确处理 loading / error 状态
- [ ] TypeScript 类型是否完整

**数据库**
- [ ] 是否有必要的索引
- [ ] 字符集是否为 utf8mb4
- [ ] 是否包含软删除字段 deleted

### 自动化验证

# 后端：编译 + 测试
cd backend && mvn clean test

# 前端：类型检查 + Lint
cd frontend && npm run type-check && npm run lint

## 注意事项

### 安全红线

| 禁止 | 原因 |
|------|------|
| 将 `.env`、密钥文件发给 AI | 敏感信息泄露 |
| AI 直接修改生产配置 | 未经 Review 的风险 |
| 信任 AI 生成的 SQL 直接上生产 | 可能有性能或逻辑问题 |
| 跳过权限校验"简化开发" | 安全漏洞 |

### 常见 AI 幻觉问题

| 问题 | 应对 |
|------|------|
| 引用不存在的类/方法 | 对照项目实际代码验证 |
| 使用过时的 API | 检查 pom.xml / package.json 版本 |
| 生成与项目风格不一致的代码 | 提供范例文件作为参考 |
| 权限标识命名不一致 | 对照现有模块命名规范 |

### 效率提升技巧

1. **维护 `.cursor/rules`**：一次配置，持续生效
2. **保存常用 Prompt**：团队共享 Prompt 模板库
3. **@ 引用文件**：比粘贴大段代码更高效
4. **分模块生成**：避免一次生成过多文件导致质量下降
5. **结合代码生成器**：标准 CRUD 用生成器，复杂逻辑用 AI
