## 设计原则

1. **RESTful 风格**：资源导向，HTTP 方法语义明确
2. **统一响应**：所有接口返回 `Result<T>` 包装
3. **版本管理**：URL 前缀 `/api/v1/`（可选，初期可用 `/api/`）
4. **幂等性**：GET / PUT / DELETE 幂等，POST 非幂等
5. **安全性**：所有业务接口需 JWT 认证 + 权限校验
6. **文档先行**：接口开发前先定义 Swagger 注解

## 统一响应格式

### 成功响应

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

### 分页响应

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "records": [],
    "total": 100,
    "pageNum": 1,
    "pageSize": 10
  }
}
```

### 失败响应

```json
{
  "code": 500,
  "msg": "用户名已存在",
  "data": null
}
```

### Java 实现

```java
@Data
public class Result<T> {
    private int code;
    private String msg;
    private T data;

    public static <T> Result<T> success(T data) {
        Result<T> result = new Result<>();
        result.setCode(200);
        result.setMsg("操作成功");
        result.setData(data);
        return result;
    }

    public static <T> Result<T> fail(int code, String msg) {
        Result<T> result = new Result<>();
        result.setCode(code);
        result.setMsg(msg);
        return result;
    }
}
```

## 错误码规范

| 错误码 | 说明 | 场景 |
|--------|------|------|
| 200 | 成功 | 正常响应 |
| 400 | 请求参数错误 | 参数校验失败 |
| 401 | 未认证 | Token 缺失或过期 |
| 403 | 无权限 | 权限不足 |
| 404 | 资源不存在 | 数据未找到 |
| 500 | 服务器内部错误 | 未预期异常 |
| 1001 | 用户名已存在 | 业务异常 |
| 1002 | 用户不存在 | 业务异常 |
| 1003 | 密码错误 | 业务异常 |
| 1004 | 角色已被分配 | 业务异常 |
| 1005 | 菜单存在子菜单 | 业务异常 |

## 认证与鉴权

### 认证流程

```
1. POST /api/auth/login     → 返回 JWT Token
2. 后续请求 Header 携带：Authorization: Bearer {token}
3. Token 过期 → POST /api/auth/refresh 刷新
4. POST /api/auth/logout    → 注销（清除 Redis 缓存）
```

## 接口命名规范

### URL 规范

```
/api/{模块}/{资源}              资源集合
/api/{模块}/{资源}/{id}         单个资源
/api/{模块}/{资源}/{id}/{动作}  特殊操作

示例：
GET    /api/system/user/list          用户列表
GET    /api/system/user/{id}          用户详情
POST   /api/system/user               新增用户
PUT    /api/system/user               修改用户
DELETE /api/system/user/{ids}         删除用户（支持批量，逗号分隔）
POST   /api/system/user/export        导出用户
PUT    /api/system/user/resetPwd      重置密码
PUT    /api/system/user/changeStatus  修改状态
```

### HTTP 方法

| 方法 | 用途 | 幂等 |
|------|------|------|
| GET | 查询 | 是 |
| POST | 新增 / 非幂等操作 | 否 |
| PUT | 全量更新 | 是 |
| PATCH | 部分更新 | 是 |
| DELETE | 删除 | 是 |

## 接口文档

### Knife4j 访问

启动后端后访问：**http://localhost:8080/doc.html**

### Controller 注解示例

```java
@Tag(name = "用户管理", description = "用户 CRUD 及状态管理")
@RestController
@RequestMapping("/api/system/user")
public class SysUserController {

    @Operation(summary = "用户列表", description = "分页查询用户列表")
    @PreAuthorize("@ss.hasPermi('system:user:list')")
    @GetMapping("/list")
    public Result<PageResult<SysUserVO>> list(
        @Parameter(description = "查询条件") SysUserQueryDTO query) {
        return Result.success(userService.listUsers(query));
    }

    @Operation(summary = "新增用户")
    @PreAuthorize("@ss.hasPermi('system:user:add')")
    @PostMapping
    public Result<Void> add(
        @Valid @RequestBody SysUserDTO dto) {
        userService.createUser(dto);
        return Result.success(null);
    }
}
```
